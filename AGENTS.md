# Digital Listen — Agent Instructions

## Project Overview

**数字听力训练 (Digital Listening Training)** — A Vue 3 + TypeScript + Vite SPA for practicing English listening. See [README.md](./README.md) for full description and TTS engine configuration.

## Quick Start

```bash
npm install        # installs deps; postinstall copies Piper runtime assets to public/piper/
npm run sync-piper # FIRST RUN: downloads the ~60MB en_US voice model into public/piper/voices/
npm run dev        # start dev server
npm run build      # type-check + production build (vue-tsc -b && vite build)
npm run preview    # preview production build
```

> No test framework is installed. There are no test commands.

## Architecture

- **Single-page app** — no router, no state management library (Pinia/Vuex). Module switching uses `v-if`/`v-show` in `App.vue`.
- **UI layout** — `src/App.vue` groups settings into two `<fieldset>` sections (模块参数 / 语音与显示); status bar shows progress + speaking + shortcuts.
- **TTS composable** — `src/composables/usePiperTts.ts` drives the bundled Piper WASM worker. The prebuilt worker is copied to `public/piper/piper_worker.js` and patched by the sync script (see below). There is no OS Web Speech API path and no HTTP engine — Piper is the single, unified engine.
- **Practice generators** — `src/utils/practiceGenerators.ts` generates items; `speakText` is produced by `src/utils/numberToWords.ts` (whole-number reading) and `src/utils/dateToWords.ts` (deterministic English date). Phone numbers stay digit-by-digit.
- **CSS** — no framework. Styling in `src/style.css`.
- **Piper assets** — `public/piper/` is gitignored and regenerated by `scripts/sync-piper-assets.mjs` (`npm run sync-piper` / `postinstall`). The script copies the prebuilt worker + onnxruntime subset from `node_modules/piper-wasm/build/`, downloads the voice model, and patches the worker (length_scale override, single-thread onnxruntime, BigInt int64 tensors).

## Key Implementation Details

- **Settings persistence**: `localStorage` key `digital-listen:settings:v1`. Schema changes must handle backward compatibility with `readPersistedSettings()` type guards. (The legacy `voiceURI` field is no longer written but is silently ignored on read.)
- **Keyboard shortcuts**: Global `window.keydown` listeners for `Space` (repeat), `→` (next), `R` (restart). `isInteractiveTarget()` guards against firing inside text-entry controls (`input, textarea, select, [contenteditable]`) only — shortcuts deliberately still fire when a `<button>` is focused; `Space` calls `preventDefault()` to suppress the focused button's activation.
- **TTS engine**: Piper WASM only (unified). `usePiperTts` primes the engine on mount (silent synthesis of "one" to load + cache the ONNX session), then serves real speaks from cache. Rate presets map to Piper `length_scale` (normal=1.0, slightlyFast=0.85, fastest=0.7).
- **Async safety**: `usePiperTts` uses a `speakGeneration` counter plus a FIFO `pendingGens` queue and a `suppressUntilGen` watermark. `stop()` (e.g. on module switch) sets the watermark so in-flight worker outputs are ignored rather than played — always respect this when adding new async TTS logic.
- **Autoplay**: first `Audio.play()` may be blocked without a user gesture; `NotAllowedError` surfaces a hint telling the user to click then press 重复发音.

## Known Issues / Cleanup Opportunities

- No mobile responsiveness testing done.
- The Piper worker is single-threaded (`numThreads=1`) for cross-origin-isolation safety; large-number synthesis is still fast (~300ms cached).

## TypeScript Configuration

- Strict mode enabled (`noUnusedLocals`, `noUnusedParameters`, `noFallthroughCasesInSwitch`)
- `erasableSyntaxOnly` — non-const `enum` and `namespace` are disallowed
- TypeScript ~6.0.2 — very modern; some older patterns may be incompatible
